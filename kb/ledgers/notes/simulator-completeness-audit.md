# Simulator completeness audit

This note is the active summary for simulator-complete use.

## Meaning
The KB target is **verified simulator completeness**:
- enough structured canon to compute Tower mechanics
- enough contracts to route all contributors
- explicit input registries for account-state families
- fail-closed handling where evidence is incomplete

## New v46 closure move
v46 closes the missing **input-family surface** problem by surfacing active canonical registries for:
- relic
- player_stuff
- theme_song
- unlock

These are simulator-relevant inputs, but they are not universal ladders shared by every account.
The frozen KB therefore defines the input schema and routing rather than inventing per-account values.

## Remaining real gaps
The highest-value remaining simulator gaps are:
1. full lab closure for defense percent and wall fortification curves
2. even named-UW structured coverage across the full roster
3. more normalized vault/economy surfaces where simulator use depends on them
4. promotion of source-backed formulas from sourced registries into canon where evidence is sufficient


## v48 update
The package now closes two major simulator-shape gaps: normalized UW identity/track routing and normalized bot identity/runtime routing. Remaining work is no longer broad family surfacing; it is the harder job of exact runtime proof for unresolved micro-precedence and any still-missing source-backed constants.


## v50 update
This pass normalized perk effects, guardian identity/tracks/routing, and economy resource/vault identities. The package still should not claim final verified accuracy until the dedicated audit phase is completed.


## v51 update
Cards are now normalized into entity, effect, routing, and unresolved-surface registries. Economy now explicitly fences vault-node numeric ladders instead of leaving that boundary implicit.
