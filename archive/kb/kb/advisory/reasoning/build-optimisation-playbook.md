# Build Optimisation Playbook

## Objective
Provide a repeatable way for a GPT to recommend the strongest build changes for a given account state.

## Primary optimisation dimensions
1. run length
2. coins per hour
3. cells per hour
4. tournament wave
5. reliability / variance

## Core decision rule
Every recommendation should be classified into one of four buckets:
- survivability extension
- kill conversion improvement
- economy multiplier improvement
- consistency / control improvement

## Account-stage interpretation
### Early
Focus on workshop efficiency, card slots, core economy unlocks, and cheap multiplicative gains.

### Mid / hybrid
Focus on balancing survivability with better kill conversion, Black Hole / Golden Tower synergy, and selective UW development.

### Late / tournament
Optimise burst control, uptime thresholds, boss handling, and battle-condition resilience.

## Comparative framework
For each candidate upgrade evaluate:
- direct effect on limiting subsystem
- synergy with existing build
- cost efficiency
- whether it solves the current death mode

## Common limiting subsystems
- boss burst
- fleet burst
- protector stall
- insufficient economy overlap
- insufficient control coverage
- insufficient kill speed

## Recommended output template
- Current limiting subsystem
- Best 3 upgrade paths
- Expected reason they work
- Reason they may fail
